Graph:一群 AI 怎麼分工

一個 agent 扛不動時,把很多個接成一張分工圖

▶ 看影片 🎓 L4 工程 🎬 8 個段落 🀄 投影片 + 逐字稿
本集開場

大家好,歡迎回到《從問 AI 到用 Agent》,這是六種工程系列的最後一集。前面我們讓一個 AI 會想、會做、站得穩。但有些任務,大到一個 AI 根本扛不動。這時候你需要的,是「一群 AI 分工合作」,而怎麼安排它們的分工,就叫 graph。它是這系列裡最新、也最容易做壞的一個。我用「一間餐廳」當例子,把它是什麼、什麼時候該用、又為什麼很多人一用就翻車,講清楚。

1

先想:一間餐廳怎麼出一桌菜

🍽️
  • 1接單、備料、炒鍋、擺盤、傳菜、結帳
  • 2很多人各做一格,不是一個人全包
  • 3有分工、有順序、有人把關出餐
逐字稿

先想一間餐廳,尖峰時段要出一桌菜,它怎麼運作?不是一個超人從頭做到尾。而是:前台接單、備料區切菜、炒鍋師傅下鍋、擺盤、傳菜、最後結帳——很多人,各做自己那一格,一格交給下一格。有分工、有先後順序,關鍵的地方還有人把關,菜不對不准出。一個 agent,就像一個廚師;當任務大到一個廚師忙不過來,你需要的,就是把它變成「一整間分工清楚的餐廳」。這就是 graph 想做的事。

2

①Graph 是什麼

🕸️
  • 1多個 agent 的「分工圖」
  • 2有哪些角色、誰把工作交給誰
  • 3像一張組織圖 + 出餐動線
逐字稿

第一段,graph 是什麼。graph 中文是「圖」的意思,但這裡不是圖表,是「分工圖」。它畫的是:這個任務,拆成哪些角色、每個角色做什麼、誰做完交給誰。你可以想成一張公司的組織圖,加上一條「工作怎麼流動」的動線。前面的 loop 是「一個 agent 自己繞圈」,graph 則是「很多個 agent、還有一些固定步驟,接成一張網,一起把大事做完」。從一個人,到一整個團隊,這就是 graph 這一層在處理的事。

3

②怎麼運作:節點 + 流轉 + 把關

🔗
  • 1節點:每一格做一件事
  • 2流轉:這一格做完,交給哪一格
  • 3把關:關鍵的地方,放一個人審
逐字稿

第二段,它怎麼運作,三個東西。第一,節點:圖上的每一格,負責做一件事。第二,流轉:定義這一格做完,要把結果交給哪一格,工作沿著線流動。第三,把關:在關鍵、或後果嚴重的地方,放一個檢查點,常常是「讓一個人來審一下」再放行。這裡有個很多人不知道的重點:節點不一定都是 AI。有些格子是固定的程式、有些是人的審核。graph 的藝術,是安排「哪一格用 AI、哪一格用固定程式、哪一格要人把關」。

4

③好處:大任務拆得動

✨
  • 1一個 agent 扛不動的,拆成很多格就做得動
  • 2每一格範圍小、好控制、好檢查
  • 3能平行:好幾格同時做,更快
逐字稿

第三段,好處。最直接的:一個 agent 扛不動的大任務,拆成很多格,就做得動了。而且每一格因為範圍小,反而更好控制、更好檢查——你知道每一格該產出什麼,錯了抓得到是哪一格。另外還能平行:好幾格沒有先後關係的,可以同時開工,整體更快。聽起來很美好對不對?這也是為什麼 graph 這個概念一出來,大家都很興奮。但接下來,我要講一個很重要、我自己親身踩過的坑,免得你一頭栽進去。

5

反面教材:亂組,會空轉一整天

🔥
  • 1我自己踩過:定了一組固定角色的團隊
  • 2它們互相回報、互相改,一整天不收斂
  • 3根因:沒給一條「做到哪算完成」的線
逐字稿

講個我自己真的踩過的坑。我一開始做多 agent,想說分工很漂亮,就定了一組固定角色的團隊,讓它們互相協作。結果呢?它們互相回報問題、互相修改,一個改完另一個又有意見,繞了整整一天,完全沒有收斂。事後我才想通:根因是我從頭到尾,沒給這張圖一條「做到哪裡、就算整件事完成」的線。沒有那條線,一群 AI 湊在一起,只會互相製造工作,永遠停不下來。這是 graph 最經典、也最貴的死法。

6

硬數據:別以為多就是強

📉
  • 1錯誤會放大:三個九成準的串起來剩七成三
  • 2固定預算下,單一 agent 常常贏過多 agent
  • 3別為了「多 agent」而多 agent
逐字稿

而且這不只是我個人經驗,有幾個很殘酷的數據。第一,錯誤會沿著鏈路放大:三個各自九成準的 agent 串在一起,整體只剩七成三。第二,研究發現,在一樣的運算預算下,單一 agent 在很多任務上,反而贏過一堆 agent 硬湊——很多「多 agent 比較強」,其實只是花了更多錢。第三,業界大量的多 agent 系統,失敗率高得驚人,而且多半是「架構設計」的問題,不是模型不夠聰明。結論很簡單:別為了「多 agent」而多 agent。

7

④怎麼用:最後手段,不是預設

🧭
  • 1先確定「一個 agent 真的不夠」
  • 2能一個 loop 做完,就別開整間餐廳
  • 3要組,就給死一條「什麼叫完成」的線
逐字稿

第四段,那到底怎麼用?一句話:graph 是最後手段,不是你的預設選項。動手前先確定「一個 agent、一個 loop,真的扛不動這件事」——如果一個人做得完,就別大費周章開一整間餐廳。真的需要組 graph 了,務必做一件事:給死一條「什麼叫完成」的線,就是前面 loop 那集講的可驗證標準,讓整張圖知道什麼時候該收工。有了那條線,再加上關鍵處的人把關,你的餐廳才不會變成一群人瞎忙一整天。

8

這集帶走一句話

💡
  • 1Graph = 多個 agent 的分工圖
  • 2不是取代 loop —— 一個 loop 是圖裡的一個節點
  • 3一個人做得完,就別急著開整間餐廳
逐字稿

這集帶走一句話,也幫這個系列收尾:graph,就是把很多個 agent 接成一張分工圖,去做一個扛不動的大任務。但記住,它不是取代 loop——一個 loop,只是這張圖裡的一個節點。你不是從 loop「畢業」到 graph,而是當一個真的不夠時,才把好幾個組起來,而且要付出協調、可能失控的代價。所以那句話送給你:能一個人做得完,就別急著開整間餐廳。六種工程到這裡講完了,從一句 prompt,到一整張 graph,希望你現在都分得清、用得出來。我們下次見。
